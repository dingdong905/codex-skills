# 论文研究栈架构

## 目标

研究能力由四层组成：

1. 薄编排器 academic-search：只识别领域、路由和合并跨领域证据。
2. 专业 Skill：维护该领域的问题结构、来源优先级、质量标准和安全边界。
3. 统一工具层 research-toolkit：维护 API、公共字段、去重与标识符核验。
4. 评测体系 evals/research-stack：用固定用例衡量路由、真实性、领域质量、安全和效率。

## 调用关系

    用户问题
       │
       ├─ 明确 AI/计算机 ─────────> ai-computing-research
       ├─ 明确医学/健康 ──────────> biomedical-evidence
       └─ 模糊或跨学科 ───────────> academic-search
                                      ├─ 分解并路由
                                      └─ 合并证据账本

    专业 Skill ──检索/核验──> research-toolkit ──官方公共 API
          │
          └─领域评价、反证、现实边界与安全

Skill 之间不是代码级强依赖：如果共享脚本不可用，专业 Skill 可以回退到当前环境已有连接器、官方 API 或浏览器，但输出必须保持统一证据字段。这避免因某个安装路径或工具失效让整个研究流程停摆。

## 统一证据契约

工具层输出：

- query log：来源、查询式、时间、条数。
- paper records：题名、作者、日期、venue、标识符、摘要、版本、OA、撤稿状态和来源。
- warnings：限流、缺字段、解析或访问问题。

专业层追加：

- evidence claim 与强度理由。
- limitations 与最强反证。
- safety flags。
- practical implication 与不可推出的行动。

## Token 预算

- 路由前不加载所有领域参考资料。
- 首轮每个来源通常只取 10–20 条元数据。
- 去重和初筛后只深读 5–10 条，真正承重全文更少。
- 跨步骤传递证据账本，不反复携带完整正文。
- 以“新增证据是否改变判断”为停止条件。

## 上游替换

数据源适配必须停留在 research-toolkit；专业 Skill 不复制 HTTP/API 代码。替换上游时：

1. 新适配器输出同一 schema。
2. 通过离线 parser、normalize、dedupe 测试。
3. 对标识符做在线冒烟测试。
4. 运行固定领域用例，确认质量和 Token/工具调用没有退化。

## 新领域准入

历史、地理、天文、社会学、哲学等新 Skill 只有满足以下条件才进入默认路由：

- 有独立 description，和现有领域少重叠。
- 有领域特有来源、证据对象和评价规则，而非复制通用模板。
- 至少 5 个代表任务、2 个反证/失败任务和 1 个跨领域路由任务。
- 不存在虚构引用，标识符核验率达 100%。
- 相比通用回退，在盲评中提高领域质量，且单领域 Token/工具调用不显著增加。

评测未达标时继续使用明确标注的通用回退，不为了目录完整而添加低质量 Skill。
