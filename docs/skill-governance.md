# Skill 抽象与案例分层规范

## 范围与判断

适用于本平台仓库内新建、修改、导入和迁移的 Skill，包括 AI 生成的文件。目标是使技能跨任务可复用，把实例事实与通用约束分开。目录统一使用单数 example/，放在每个 Skill 内，确保复制安装后案例仍可用。

更换设备、项目、公司或任务，规则仍成立则属于通用层；依赖某次输入、输出、环境或特定对象才能成立则属于案例层。抽象不是删除技术细节：精确 API 字段、参数化命令、算法、平台权限与版本条件是执行契约，按需保留。

| 位置 | 内容 |
| --- | --- |
| SKILL.md | 触发范围、共用判断、关键约束、工作流、输出契约、条件性资源路由 |
| references/ | 通用方法、协议、schema、领域规则与条件性操作细节 |
| scripts/ | 接收参数的可复用工具；路径与业务输入由调用方传入 |
| assets/、templates/ | 素材或空白模板；填好的模板属于案例 |
| example/ | 具体项目/设备记录、完整演示、填好的报告、合成输入输出、题目复盘 |
| tests/、evals/ | 自动测试专用 fixture、评测输入与评分规则，保持机器消费契约 |
| 仓库 docs/ | 仓库维护、来源与适配记录；不能用它规避技能内案例分层 |

## AI 编写与更新流程

1. 先读最近的 AGENTS.md；按目标平台元数据和工具能力编写，保留既有调用策略。
2. 先列通用规则与案例事实。具体名称、路径、地址、数值结论从通用指令拆出；可执行输入参数化。
3. 只创建确有内容的目录。新增案例写入本 Skill 的 example/，同步 index.json；没有案例无需创建它。
4. SKILL.md 按任务条件链接案例或参考；案例不是必读、不是默认输入，不继承历史授权与环境状态。
5. 移动时同步入口、相对链接、脚本说明、评测与安装文档；保留出处和许可证。安装包不链接到另一平台仓库。
6. 通用脚本的演示数据也外置。仅由测试消费的 fixture 留 tests/ 或 evals/；兼作教学演示时优先 example/，测试引用它。
7. 运行治理检查、目标平台结构校验与受影响的行为检查。再复核：去掉案例能否完成工作、规则是否从单个失败过度概括、是否区分观察与推演。
8. 交付报告检查结果和未核实部分。结构通过不等于语义正确，不承诺未来 AI 永不偏离规范。

实际任务产物、用户学习进度先放用户项目；只有用户要求沉淀且可脱敏复用时才进入 Skill。案例不包含凭据或私密会话。历史本机路径不代表当前可用路径。

## 案例登记契约

example/index.json 使用 version=1 与非空 cases 数组。每项填写：

- id：小写字母、数字、连字符，在本 Skill 内唯一。
- kind：observed（历史实测）、synthetic（合成）、teaching（教学或演示）。
- files：相对 example/ 的路径数组；所有案例文件登记，不能越界或重复。
- scenario：何时需要这个案例。
- preconditions：输入、环境和必要前提。
- expected：预期行为或历史实际结果；未完成、未验证必须明说。
- limits：不适用范围、需重新核验的状态、不得作为默认值或授权的部分。
- source：原文件、外部来源或合成方法；保留原许可。
- verified_at：原实测/核验日期，未知用 unknown；迁移日期不能冒充验证日期。

Markdown 案例保留原内容与来源；JSON、代码和其他样例保持可执行格式，元数据集中登记在 index.json。

## 检查

在平台仓库根目录运行：

    python -B scripts/lint_skill_governance.py

检查 frontmatter 基本字段、资源引用、案例目录命名、明显本机路径、案例正文混入、登记完整性与文件边界。CI 对 pull request / push 执行同一命令。它不替代官方校验、事实核验、语义审阅或原有测试。

最小参数化语法、纯字段定义可留 references/；成组的具体输入、配置与结果放 example/，通用层按需引用。不要靠改标题掩盖案例。
