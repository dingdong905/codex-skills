# Codex / WorkBuddy 双轨维护约定

## 决策

Codex Skills 与 WorkBuddy Skills 是两个独立发布物。允许存在同名、同源或功能相近的 Skill；不通过删除一侧、软链接、安装时拼接或共享运行时文件做跨平台去重。

目标是保持平台原生可靠性，而不是追求文件级一致。

## 可以迁移的内容

- 已被真实任务验证的决策规则和失败处理；
- 领域 reference、输出 schema 和确定性算法；
- 不含平台私有假设的脚本；
- 正向、负向、边界和安全回归案例；
- 真实失败形成的窄修复。

## 必须重新适配的内容

- frontmatter、UI metadata 和显式/隐式调用策略；
- 工具、MCP、Connector、文件展示和安装路径；
- 权限确认、外部写操作和持久化边界；
- 平台已有能力，避免写出不存在的工具名；
- 验证器、测试命令和最低运行版本。

不得只改目录名就宣称迁移完成。

## 迁移流程

1. 写清来源 Skill、要迁移的独特能力和目标平台缺口。
2. 只搬运会改变决策、提高可靠性或减少重复劳动的内容。
3. 用目标平台格式重写入口；大段条件性内容放到 references。
4. 将可机械判断的高风险步骤脚本化，并使用无真实敏感信息的合成 fixture。
5. 为误触发、边界、安全和 Token 预算增加回归案例。
6. 运行目标平台官方结构校验、脚本测试和相关评测。
7. 记录差异；之后两侧可以独立演化，不要求逐行同步。

## Token 原则

- 只比较每个平台实际会常驻的名称和 description，不把所有 Skill 正文算作常驻上下文。
- description 负责精确发现，不承载完整流程。
- `SKILL.md` 只保留共享决策、硬约束、资源路由和输出契约。
- references 按模式读取；scripts 直接执行，非维护时不加载实现。
- 显式专用、低频或正文较大的 Skill 应关闭隐式调用。
- 每次迁移使用同一口径记录 Skill 数、description 字符、入口正文字符和回归结果。
