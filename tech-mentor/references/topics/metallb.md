# MetalLB 课程样例

这是课程设计样例，不是当前版本的操作手册。正式教学前必须核验 MetalLB 与 Kubernetes 官方文档、当前版本及实验环境。

## 目标

用户能够解释裸金属 Kubernetes 中 `LoadBalancer` 服务的入口缺口，区分 MetalLB controller 与 speaker，比较 L2 与 BGP 宣告，并沿真实流量路径排障。

## 类型

知识型为主，部署与排障属于技能型。生产环境只读；所有故障注入仅限已确认的教学或测试环境，并逐次取得授权。

## 路径

1. **Service 流量分段**：区分集群内转发与集群外入口；解释裸金属环境中 `EXTERNAL-IP` pending 的责任缺口。
2. **组件分工**：controller 负责 IP 分配和状态，speaker 负责向网络宣告；用真实 Pod 拓扑验证。
3. **L2 模式**：理解 ARP/NDP 宣告、单入口节点和故障切换窗口；不把它误解为多节点轮询。
4. **BGP 模式**：理解邻居关系、路由宣告和 ECMP 的 per-flow 特性；无路由器环境时只做模拟并标注。
5. **链路排障**：客户端路由/邻居表 → 入口节点 → kube-proxy 或替代数据面 → Endpoint → Pod，逐段寻找证据。

## 检验标准

- 能解释“Service 已有集群内规则但仍 pending”为什么不矛盾。
- 能准确说出 controller 与 speaker 的职责边界。
- 能比较 L2 与 BGP 的宣告对象、流量入口和收敛行为。
- 面对“已有 EXTERNAL-IP 但访问不通”，能给出前三个验证点及每点证据。
- 在测试环境独立完成一次部署或故障定位；无法实作时标为未验证。
