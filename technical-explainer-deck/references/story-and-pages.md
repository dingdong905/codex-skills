# 技术演示的叙事与页面模式

## 页面模式

| 页面任务 | 推荐表达 | 强制检查 |
| --- | --- | --- |
| 技术挑战地图 | 分层问题树或系统边界图 | 每个挑战说明影响对象，避免只有名词 |
| 概念与单位 | 定义、量纲、一个算例 | 单位与精度一致，概念不混用 |
| 系统架构 | 分层架构或数据流 | 标清边界、方向、关键接口和图例 |
| 机制解释 | 3–6 个阶段的分步图 | 每步只解释一个状态变化 |
| 参数到场景 | 参数、阈值、场景三列映射 | 不把厂商峰值直接当业务性能 |
| 对比矩阵 | 少量决定性指标 + 结论栏 | 统一条件；缺失值不能当零 |
| 演进时间线 | 时间、版本、变化、影响 | 写清发布日期和信息截至日期 |
| 生态兼容 | 依赖图或支持矩阵 | 区分官方支持、社区支持和推测 |
| 故障定位 | 现象、证据链、节点、验证 | 根因与相关性分开 |
| 选型结论 | 推荐、适用条件、反推荐条件 | 说明代价、风险和下一验证动作 |

## 芯片与 AI Infra 专项

- 峰值算力必须带数据类型、稀疏性、频率或加速条件；`TOPS` 与 `TFLOPS` 不直接横比。
- 训练和推理分开；模型规模不能替代 batch、sequence、并行策略和利用率。
- 端到端性能至少考虑计算、显存/内存、互联、存储、软件栈和功耗/散热。
- 厂商 benchmark 与独立 benchmark 分开；规格表与实测表分开。
- 价格写币种、税费/折扣口径、采购或租赁模式和日期；无法核验时用区间或待确认。
- 供应与兼容性属于高时效结论，在页内或备注标注 `截至 YYYY-MM-DD`。

## 密度决策

出现任一条件即考虑拆页：

- 标题同时含两个并列主题
- 超过一个主图或两个独立数据问题
- 正文必须低于 15pt 才能放下
- 表格超过 7 个可见数据列
- 架构图需要超过 6 个说明段落
- 一页同时解释“是什么、为什么、怎么选、怎么做”

拆页后使用一致的全景图，并在每页只高亮当前层或当前路径，保持观众方位感。

## 演讲备注

备注适合放：术语展开、数据来源、口径、演示顺序、30–60 秒讲稿、可能追问和备用解释。不要把无法核验的断言藏在备注里。
