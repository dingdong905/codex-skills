# Tara Android 实测操作参考

截至 2026-10-06，在 Android 16、小米 14、Tara Android 3.2.1（`com.taraai.tara`）验证。应用更新、屏幕尺寸、键盘、连接或 UI 状态变化后重新检查；这里是操作经验，不是永久可执行坐标。

## 产品与授权边界

- 官方网站：https://taraai.cn/ 。Android 商店说明：https://app.mi.com/details?id=com.taraai.tara 。应用内 `我的 → 账号设置 → 怎么玩 Tara` 可打开产品指南，WebView 初次进入可能尚未加载，等正文出现再读取。
- 指南说明：陌生人通常先与对方的 Tara 聊天；动态会成为介绍用户的社交素材；`Tara 在学` 决定对话是否用于社交学习。实际开关和用户意愿需要当次核对。
- 区分编辑草稿、已发布、已置顶、发给对方 Tara、本人回复。AI 的即时回复不能作为本人愿意见面、单身或所在地的确定证据。
- 创建资料或任务不自动授权给其他用户发消息；需要当次用户明确授权。已有明确授权的同一任务内不重复索取授权，但后续自动审批拒绝仍须按工具返回处理。
- 研究产品指南、公开状态和当前目标会话只读取任务必要部分；经验文档不保存用户个人资料、对方身份清单、照片或聊天全文。

## 页面识别与转场

优先用 `uiautomator dump` 的 `content-desc` 和当次 `bounds` 定位。常见值：

| 页面或控件 | 已观察到的标识 |
| --- | --- |
| 发现 | `page:discover`、`Discover recommend nickname`、`Discover chat entry` |
| 我的 | `page:my-profile`、`Social settings`、`My profile skill entry` |
| 状态编辑 | `page:update-status`、`Update status content input`、`Update status post button` |
| 状态标题 | `page:select-status`、`Select status custom state input` |
| 任务编辑 | `page:task-publisher`、`Task publisher title input`、`Task publisher description input` |
| 任务第二步 | `state:task-publisher-prompt`、`Task publisher publish button` |
| 会话 | `page:im3-conversation-detail`、`Conversation title`、`Conversation message input`、`Conversation send message button` |
| 会话消息 | `Conversation message bubble mine`、`Conversation message bubble peer Tara` |

- 发现页横向左右滑动切换相邻推荐，纵向滑动是在当前对象的动态里滚动。本次左右两侧都曾找到未看过的卡片，不把滑动方向等同于推荐的新旧顺序；用昵称验证是否真的翻页。同方向反复无变化时先核对转场、滚动位置和另一方向，不持续盲滑。
- 页面滚动、键盘弹出、草稿增高、半屏/全屏会话切换，都会改变坐标。先确认页面稳定，再取当次控件；导航后不沿用旧页面的输入框位置。
- 在新窗口中首次导出的树可能仍显示转场信息；若页面标识、截图和预期不一致，重新导出后再操作。
- 发现页出现推荐等待/倒计时，表示当前批次暂时耗尽；可回看现有卡片，不能声称已经取得新的推荐。
- 返回控件比假定 Android 返回键有效更可靠。返回会话或断线后草稿可能丢失，重开后先核对，不把旧草稿视为已经发送。

## 筛选和自然开聊

- 按用户当次给出的偏好筛选。用户强调外形时先看公开真人照片；卡片兴趣介绍、AI 头像和自称不能代替照片。照片外形评价具有主观性，不据照片推断年龄、所在地或单身状态。
- 推荐卡片未必显示城市、年龄或恋爱意图。用自然话题逐步了解这些信息，不把推荐当作已满足所有条件。
- 开场用一条真实共同话题和一个容易回答的问题。只介绍用户确实提供过的经历、兴趣和城市；不用模板批量群发，不凭空声称自己看过作品或玩过某款游戏。
- 自动欢迎语出现在输入前，不等于对本次消息的回复。发送后检查己方消息气泡和接收方身份，再读取相关的新回复。
- 打开推荐对象的会话可能已有己方消息或引用开场；先核对已发送内容再接话，不因首次手动打开就假定是空白会话。
- 消息主页可先用 `Message home conversation row` 和目标昵称定位当前行，读取该行的最新预览与未读标记。实测可访问树的行控件与文本不一定是父子关系，不能只查行节点后代；必要时按当次行 bounds 读取已核对目标的可见文本，不输出其他会话。
- 对方 Tara 的回答可提供线索，条件尚不明确时不记录为确认事实。若对方明确拒绝，停止追问。

## 状态、置顶和公开任务

1. `我的 → 去更新/轻触更新状态` 进入编辑器。正文之外需要选择一个状态标签；实测只有正文且状态为空时，点发布仍停在编辑器，不能报告成功。
2. 可以用 `写状态` 自定义短标签，核对 `state:update-status-selected` 再发布。返回个人页并出现对应正文，才算发布成功。
3. 该状态右侧操作菜单含 `置顶`、编辑和私密选项；置顶后确认个人页有 `置顶` 标记。
4. `我的 → 给 Tara 派个任务`：标题/正文是公开需求，实测标题计数上限 24。点继续进入 `设置聊天指令`。
5. 第二步会生成非公开聊天指令。等生成完成后核对事实与用户目标，再按需求编辑；注意自动生成指令可能把宽松偏好变成硬性排除，或过早推进交换联系方式/见面。
6. 点 `快去吧` 发布后，个人页显示 `Tara 在帮你 …` 可作为任务已创建的证据。创建成功不代表真人匹配或聊天已经成功。

## 中文输入

`adb shell input text` 不适合直接提交 Unicode 中文。先选择当次可用的最小方案：

- 已授权并已安装的 ADB Keyboard 可用 `ADB_INPUT_B64` 传 UTF-8 的 Base64；这是输入接口，不是加密。聚焦正确输入框、输入后核对实际文字，再发送或发布。
- 若需临时安装，核对官方来源、包名、权限和版本兼容性；记录原输入法，完成或停止时恢复。手机安装确认被取消时不要连发安装命令。只有用户准备好或明确要求重试后再发起。
- 没有助手时，可使用当前原生拼音键盘：先截图识别当次字母/候选区，按短句输入拼音并选候选，最后核对整条草稿。坐标由截图取得，不跨分辨率、键盘布局或页面状态复用；候选词不是总能正确。
- 输入脚本与发送动作分开。先完成草稿核对，再根据当次接收方标题和发送按钮提交，防止误发、重复发送或拼音选词错误。

## 黑屏和断线

- 空树或全黑截图先区分休眠、锁屏和 `FLAG_SECURE`。`dumpsys power` 的 `mWakefulness=Asleep` 与 `dumpsys window` 的锁屏状态说明需要用户解锁，不能把黑屏直接当作应用防截屏，也不能绕过锁屏。
- `adb devices -l` 为空时再查 `adb mdns services`；没有已授权可用连接就请用户重新接线/完成手机端调试授权。
- 恢复后重新选择序列号或 transport ID，再导出当前页面；不要继续点击断线前的旧坐标，也不要重复发送未核实状态的消息。
## 2026-10-07 补充验证

- 本人消息可标识为 `Conversation message bubble peer`，AI 消息为 `Conversation message bubble peer Tara`；本人会话还观察到 `state:im3-relation-human-direct`。按当次 UI 来源区分，不因未读就假定是本人回应。
- `page:im3-helping-list` 的空列表提示“暂时没有人来找你的Tara聊天”；它描述收到的代聊入口，不等于公开任务不存在或运行失败。个人页任务标题／详情仍需单独核对。
- 键盘弹出时截图可能捕获动画中间帧，键盘及输入框整体暂时偏移；等待并重新核对稳定布局后再输入，不立即修改固定坐标去追逐中间帧。
- Windows 正确枚举 ADB 接口且驱动问题码为 0，但 `adb devices` 在 device、offline、空列表间变化，并有 `read failed`，说明数据通道不稳定；不据此归因为调试开关没开。核对本机 ADB 进程、USB 后端及相关日志，再用同一份无私人内容的临时文件比较 USB／无线传输和校验值。
- 本次 ADB 37.0.1 支持临时 `ADB_LIBUSB=1`，须以 `server-status` 确认实际后端；切换未立即恢复，之后已撤销，不能沉淀为有效修复。Windows 重启设备接口若返回 Access denied，则未执行成功；不要以安装或重装驱动代替尚未确诊的检查。
- 无线地址主动拒绝时，优先核对手机主页的当前 IP 和连接端口。USB 若短暂可用，可读取无线调试页作核对；本次端口已变化，实际地址连接成功。多个连接同时存在时，每次明确指定当次核对的 serial／地址。
- 若期间同时刷新了手机调试服务并插拔／更换线材或接口，恢复后的对照测试只能证明当前通道可用，不能归因于某一个动作。

## 2026-10-10 补充验证

- 本批发现页边界出现“探查完成”，并可反向回看已有卡片；核对另一侧连续无变化后才判定当前批次已浏览完。深滚动时昵称可能从 `Discover recommend nickname` 变成顶部普通文本，空昵称本身不证明耗尽。自动翻页遇到重复昵称应停下核对，避免连续盲滑。
- 向自己的 Tara 追问候选人昵称及主页卡片，实际收到 `Conversation TaraNet card message`，卡片中“继续问问她的 Tara”是进一步了解入口。实测口头介绍的城市与随后卡片出现矛盾；需核对具体卡片、指出矛盾，不能把 AI 描述当成已确认匹配。Tara 说“记下了”不代表已经产出新的推荐。
- 对方 Tara 说已递话给本人，只能记录为 AI 转达提示；尚无本人消息时，不报告本人已回复或愿意见面。
- 当前搜狗编辑框中，`adb shell input keycombination 113 29` 后单独 `input keyevent 67` 可清空己方未发送草稿，再重新输入并核对。只对已核对归属的草稿使用，不应用于已发送消息或其他用户资料。
- 临时固定竖屏前记录 `accelerometer_rotation` 和 `user_rotation` 原值；完成或中断后恢复实际改动的设置并读取验证。断线时记录尚未恢复的设置，连接恢复后优先完成。
