# 上市公司基本面与财务取证

产出有证据支撑的公司分析、同行相对评分卡和估值区间。

## 总原则

**财务指标只有放回行业和公司自身历史中才有意义。**

不得依赖单一指标排序。综合评估盈利能力、资本回报、现金转化、资产负债表、增长耐久性、治理和价格。只做同类比较：同行、相似商业模式与资本强度、相近会计制度和对齐期间。银行、保险、REIT、矿业等必须使用行业专用指标，不能生搬通用利润率或 P/E。

## 不可妥协的要求

### 1. 不得编造数字

- 每个财务数字都要标注**来源、期间、币种、单位以及合并/单体口径**。
- 找不到时写“暂无可靠数据”，并说明需要什么文件；不得凭记忆补数。
- 收入、净利润、债务、现金等关键数字尽可能双源核对，其中至少一个是一手文件。
- 当前股价和市值可以来自交易所或行情网站，但必须标明截至时间。
- 估值假设必须公开，并用区间和敏感性表示不确定性；不得用粗糙假设给出两位小数的目标价。

### 2. 原始公告是底稿

来源优先级：

1. 年报、10-K/10-Q、交易所公告、季度业绩、招股书、审计报表。
2. 公司发布的业绩会记录、投资者演示和业绩新闻稿。
3. 监管记录、评级报告、持股与质押数据。
4. 新闻、券商报告和聚合站只用于导航或交叉检查，不能替代原始公告。

第三方数据与公告冲突时，以公告为准，并把冲突本身记录为发现。

### 3. 年报不只是三张表

必须同时检查：

- 商业模式、战略、客户、竞争优势和风险因素；
- 3–5 年 MD&A，拆分量、价、产品结构、产能、资本开支、订单和指引兑现；
- 审计意见、关键审计事项、强调事项及适用的 CARO 附件；
- 关联交易、或有负债、诉讼和资本承诺；
- 董事会与审计委员会独立性、股权/质押趋势、薪酬、审计师变更、股东异议和股权稀释；
- 分部收入、利润、资本占用和行业运营 KPI；
- 适用时检查 ESG/BRSR、秘书审计和子公司披露。

详细年报阅读顺序见 `references/15-document-diligence.md`。

### 4. 分析而非个性化建议

可以给出多空情景、估值区间、风险和证伪条件；不得替用户决定买卖数量、仓位或给出个性化交易指令。明确说明这是研究分析，不是持牌投资建议。

## 选择深度

| 模式 | 适用请求 | 范围 |
|---|---|---|
| 快速筛查 Screen | “快速看看”“是否值得研究” | 身份、数据、淘汰条件、估值常识检查 |
| 标准 Standard | 默认“分析这只股票” | 完整流程、中等深度、报告与评分卡 |
| 深度 Deep dive | “详细”“最大深度” | 全量尽调、取证、情景估值、强反方论证 |
| 财务取证 Forensic | “利润真实吗”“现金流为何跟不上利润” | 按 `references/18-forensic-mode.md` 执行 F0–F5，不先做估值 |
| IPO | 尚未交易、DRHP/RHP/S-1、申购分析 | 按 `references/19-ipo-mode.md` 执行 I0–I7 |

开始时说明采用哪种模式。严重审计或治理红旗出现时，应从标准模式切换到财务取证；报表不可信时继续估值没有意义。

## 标准工作流

### 阶段 0：确认分析对象

确认公司、交易所、代码、ISIN、证券类型、报告币种、财年截止日、合并/单体口径、市值、企业价值和自由流通股。未上市则转 IPO 模式。

### 阶段 1：获取并验证资料

优先取得：

- 最新年报/10-K，理想情况下再取前 4 年；
- 最近 4–8 期季度公告；
- 最近 2 次业绩会记录；
- 最新投资者演示、持股结构和评级报告；
- 近年上市公司适用时取得 DRHP/RHP/S-1。

从原始文件提取至少 5 年三张表、最近 8 个季度趋势、股权结构，以及战略、风险、审计、关联交易、或有负债、治理、分部和运营数据。每项重要数字带页码或章节。

缺少文件时，直接说出具体名称，例如“请上传 FY2025 年报 PDF 和最近两次业绩会记录”，不要笼统索要“更多数据”。聚合站数字只能标为“未通过公告验证”。

执行**时效门**：

- 公司实际披露的最新期间是什么？
- 最新数据之后是否发布过新季度、评级、监管/法院决定、并购进展、管理层变更或指引更新？
- 计划写成“未来风险”的事件是否已经发生？

报告中写明：“纳入的最新期间：……；检查后续事件截至：……”。

整理数据后运行：

```bash
python scripts/verify_data.py <intake.json>
```

修复缺来源、跨源冲突、合并/单体混用、单位错误和数据过期等 error 级问题后再计算。细节见 `references/21-data-integrity-tools.md`。

### 阶段 2：行业与公司情形分类

先选择行业手册，再判断是否属于亏损成长、强周期、困境反转、分拆、控股公司、新上市、国企、连续并购或控股股东主导等情形。详见 `references/13-situations.md`。

### 阶段 3：淘汰条件与红旗

优先筛查：

- 累计经营现金流长期显著低于累计利润；
- 应收账款持续快于收入；
- 保留/否定审计意见、强调事项或审计师辞任；
- 高位或上升的股权质押；
- 关联方利益输送、频繁“一次性”项目、重述报表；
- 不透明集团结构和不可持续杠杆。

严重红旗必须放在报告前部，不能被综合评分“平均掉”。参考 `references/07-forensic-red-flags.md` 和 `references/08-governance.md`。

### 阶段 4：核心基本面

按需读取：

- `references/02-core-factors.md`：商业质量、护城河、行业、增长和再投资空间。
- `references/03-earnings-quality.md`：收入拆分、利润率、应计项、一次性项目、税率、股权激励和稀释。
- `references/04-balance-sheet-and-cashflow.md`：杠杆、偿债、到期墙、营运资金、OCF/利润和自由现金流。
- `references/05-returns-and-dupont.md`：ROIC/ROCE/ROE、杜邦、增量回报和正常化。
- `references/15-document-diligence.md`：把管理层叙事、承诺兑现、治理和分部回报与数字放在一起分析。

### 阶段 5：同行和历史比较

按 `references/10-peer-set.md` 构建同行集合。每个关键指标同时对比正确同行和公司自身 5–10 年历史。公司可以优于同行却正在自我恶化，两条基准都不能省略。

### 阶段 6：估值

按行业选择方法：银行看 P/B 与 ROE，寿险看 P/EV，REIT 看 AFFO 与资本化率，矿业看中周期 EV/EBITDA，航空看 EV/EBITDAR 等。使用 `references/06-valuation.md`。

必须加入反向 DCF：当前价格已经隐含怎样的增长和利润率？运行：

```bash
python scripts/valuation.py <inputs.json>
```

输出 EV 桥、倍数、隐含增长、两阶段 DCF 和概率加权情景；终值增长率不得高于 WACC。

### 阶段 7：风险、熊市情景与证伪

根据 `references/09-risk-and-macro.md` 写出最可信的反方论证，而不是稻草人；列出能被观察、且会证明正向逻辑错误的具体事件。

### 阶段 8：评分与写作

使用 `references/11-scoring-rubric.md` 和 `scripts/score.py` 计算行业相对评分；按 `references/12-report-template.md` 写报告。`examples/` 仅用于学习呈现方式，示例数字是虚构的，不能当作证据。

### 阶段 9：挑战结论

标准模式建议执行，深度模式必须执行 `references/20-challenge-pass.md`：攻击真正支撑结论的关键主张，核验数字来源，并测试更换同行和权重后结论是否仍成立。允许挑战后改变结论；只增加几个无关痛痒的免责声明不算审查。

### 阶段 10：交付前质检

```bash
python scripts/lint_report.py <report.md>
```

检查时效声明、数据质量、口径单位、评分门槛、熊市情景、免责声明和数字附近是否有来源。error 级问题必须修复。默认文件名为 `<TICKER>-analysis-<YYYY-MM-DD>.md`。

## 内置脚本

- `scripts/ratios.py`：比率、杜邦、应计项和现金转化。
- `scripts/score.py`：行业相对多因子评分，支持分部混合。
- `scripts/valuation.py`：EV 桥、倍数、反向 DCF、两阶段 DCF 和情景估值。
- `scripts/verify_data.py`：来源、口径、单位、跨源一致性和时效验证。
- `scripts/lint_report.py`：报告完整性和数字引用检查。

脚本只使用 Python 标准库。`scripts/benchmarks.json` 是可编辑的默认基准，不是永恒事实；有更合适的市场和期间数据时应覆盖。

## 输出契约

始终交付：

1. **报告**：开头给结论和核心风险。
2. **评分卡**：展示分类得分、权重、总分和输入，便于读者质疑具体项目。

附数据质量说明：哪些数字已验证、哪些是估计、哪些缺失，以及截至日期。

## 反模式

- 用通用指标评价银行、保险、REIT 或矿业。
- 找不到数字时插值或编造。
- 用综合分数掩盖一票否决的治理问题。
- 把聚合站当一手来源。
- 不分重点地加载全部参考资料；多数公司真正决定结论的只有 3–4 个因素。
- 把研究输出包装成个性化买卖或仓位建议。
