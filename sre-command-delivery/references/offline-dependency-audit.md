# 无源部署依赖审计

目标是判断物料按约定落位后，正式部署入口是否可以不依赖在线软件源完成。先明确本轮是检查、方案还是实施；方案请求不自动授权生产安装或更改软件源。

## 追踪真实消费链

核对当前代码版本、模块与角色、物料根、BOM 引用及归档 SHA。读取实际归档内的安装脚本，不仅检索源码。新运行时包可能只补控制端 Python/Ansible，旧节点 RPM 仍在消费链上。

分开判断：

- 包管理器本体是否由基础系统提供；没有在线源不等于没有 dnf/yum。
- 安装命令的仓库与插件设置、缓存更新、repolist、缺包回退和下载步骤是否访问外部源。无法证明联网时标为风险，不能写成已发生事实。
- 本地物料是否覆盖所需包及架构/发行版；按包名覆盖不等于依赖版本求解通过。
- 必需命令是否进入缺失检测与安装条件；归档里有包不代表所有分支会安装它。
- 每个角色是否在首次用工具前经过准备。特别检查前序 play 排除的角色、角色重叠、独立执行和部分安装状态。
- 镜像/chart/Nexus 是不同依赖；无 YUM 源不等于所有网络端点不可用。

## 证据等级

静态检查证明命令与分支存在；归档检查证明物料内容；mock 证明控制流和错误传播；只读现场检查证明当前状态。只有获得授权、在匹配系统上禁用仓库并验证本地依赖安装，才可以声明无源安装已验收。

mock 包管理器时隔离配置目录和文件写入，明确没有执行真实安装。检查失败查询是否被忽略，以及“成功标记”是否掩盖缺包。不要将模拟成功说成真实依赖闭包已安装。

## 形成可交付方案

保留已有大包与校验值；能由正式代码补充小型安装器时，不必重打全部 RPM。所有调用方应使用同一受校验、只消费本地物料的流程，缺依赖或版本冲突立即报告，不静默转在线源。不要修改仓库配置来掩盖问题。

部署入口可准备依赖；只读 check 只报告缺失，不能顺手安装。安装后的验收应使用 rpm 状态、实际命令和选定 Python 的 import，不仅匹配安装器文案。

覆盖全新节点、已有正确状态、只缺单个工具、被前序排除的角色、旧/新物料组合、缺包或校验失败、无仓库与坏仓库配置、第二次执行。列清楚已验证与待现场验证的边界。
