# 视觉验证与交付

新建或修改后打开实际页面。优先使用项目已有测试/预览和环境浏览器能力；浏览器工具的 API 以其当前文档为准，不编造旧平台工具或截图命令。

## 最小验证范围

- 与改动相关的窄屏和宽屏；若目标设备未知可先用 375px、768px 和桌面宽度，再按实际内容补查。用户明确要求 320px 等范围时纳入。
- 长文案、较大字号/缩放、加载/空/错误等受影响状态；只对实际存在的状态测试。
- 键盘焦点、可访问名称、表单标签与错误关联；弹层检查进入、退出与焦点返回。
- 项目支持暗色或动效时检查主题和 reduced-motion。
- 普通文字对比至少 4.5:1，大文字至少 3:1；必要的非文本控件边界/状态至少 3:1，按角色应用。APCA 与 OKLCH 明度不能替代声称 WCAG 合规所需的测量。

修复溢出时检查 min-width、grid/flex 轨道、长文本和定位元素，不统一给 html/body 加 overflow 裁切。图表、长表格等可有明确可操作的局部滚动，不把所有水平滚动都当错误。

## 交付

报告主要改动或问题、理由、实际验证和未验证项。审查只给排序建议；实现请求交付可运行修改和准确文件链接。视觉判断不能由想象渲染、自评分或源代码注释代替。没有运行页面时可交付静态检查，但必须明确限制。
