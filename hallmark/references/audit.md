# 审查准则

依据上游 Hallmark 的层级、具体性、克制与结构多样性思想，按当前页面任务挑选问题。不要对每个页面机械运行几十项审美禁令。

## 用户任务先于风格

先回答：用户来这里完成什么、首屏是否能识别主要信息和行动、阅读顺序与任务是否一致？只有截图时不能断言实际导航、表单提交、读屏或加载行为。

| 维度 | 要观察的证据 | 可能的改进 |
| --- | --- | --- |
| 信息层级 | 主标题、主要操作、次要信息是否争抢权重 | 调整顺序、字号、密度、对比与留白 |
| 内容具体性 | 真实产品信息、可验证证明、示例是否支持主张 | 保留真实素材；未知数据标注待确认，不造证言和指标 |
| 结构节奏 | 每节是否服务不同问题，是否机械重复相同卡片 | 按内容改用列表、比较、步骤、案例或真实产品演示 |
| 字体与配色 | 品牌一致性、字体回退、文本量、文字与背景关系 | 调整角色和尺度；不因字体常见就替换 |
| 控件状态 | 焦点、错误、禁用、加载是否清楚 | 保留原生语义并减少状态切换的布局跳动 |
| 视觉克制 | 装饰是否遮挡信息、增加加载或分散操作 | 仅移除不服务内容的装饰；不禁止有明确意图的渐变/网格 |
| 适应性 | 长文本、不同视口、缩放、暗色是否破坏阅读 | 修复容器与换行，确认图表/表格滚动方案 |

## 缺陷与建议分开

- 优先处理阻断操作、不可读、焦点被遮挡、布局溢出、虚构事实等明确问题。
- 其次处理阅读层级混乱、组件不一致、状态难分辨等有上下文证据的问题。
- 风格更换、结构变化和动效是建议，附理由与代价；不把“看起来像模板”当作唯一证据。

每个问题给出位置、观察证据、用户影响和可实施的修复。需要代码反馈时指向准确文件/行；缺乏证据时说明待验证项。用户要求评分时说明评分尺度，避免用精确分数替代事实。
