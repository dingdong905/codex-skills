# 按内容选择页面结构

结构多样性是信息组织的差异，不是每次强制换主题。已有项目的一致性优先；同类页面复用相同导航、表单与卡片是合理行为。

## 结构候选

| 内容与任务 | 合适的组织方式 | 需要的真实输入 |
| --- | --- | --- |
| 产品机制或工作流 | 问题 → 操作演示 → 关键步骤 → 边界 → 下一步 | 实际界面、操作步骤、能力限制 |
| 功能或方案选择 | 决策条件 → 比较 → 适用场景 → 行动 | 可比维度与准确差异 |
| 服务介绍 | 用户问题 → 服务过程 → 交付 → 联系方式 | 服务范围、周期及联系方式 |
| 内容/编辑型页面 | 核心观点 → 证据 → 章节阅读 → 相关内容 | 正文与可靠资料 |
| 运营或后台页面 | 状态摘要 → 任务入口 → 明细 → 异常处理 | 指标口径、操作权限与数据状态 |
| 作品/案例页面 | 作品 → 背景与限制 → 过程 → 结果 | 自有素材与可验证结果 |

页面实际只需要一部分时减少章节，不为了完成模板增加卖点、客户 Logo、统计条或 CTA。

## 结构表达的六个维度

1. 标题位置：行内、分栏、章节头；阅读顺序保持清楚。
2. 主体组织：列表、比较、时间顺序、大小分组；依据内容而不是随机。
3. 分隔语言：留白、细线、背景层；建立可理解的分节。
4. 操作表达：主次按钮和文本链接与行动代价相符。
5. 图像处理：真实产品图、示意图、用户资产；无素材时明确占位。
6. 动效：状态反馈或必要的连续性；减少动效仍能完成任务。

重设计时列出保留的业务约束与结构变化理由。控件级修改跳过页面宏结构与主题选择。需要用户自行维护的设计规范时更新项目既有文档，不自动创建 Hallmark 日志、评分印章或全局主题文件。
