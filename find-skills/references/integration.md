# 来源记录与适配验证

## 来源与比较证据

为选中的来源固定 commit SHA 和子路径。来源记录至少包含 repository、commit、path、核验日期、作者/版权归属、许可依据、导入文件/范围、适配说明。可采用仓库已有 SOURCE.json 字段。没有明确许可就记录未知，公开再分发前解决；仓库主许可不自动覆盖导入内容。保留要求的版权和许可文本。

评估脚本时查看文件读写、网络服务、依赖安装、凭证访问和自动更新行为；只读审阅即可发现的不兼容点无需执行原脚本。记录维护日期、相关提交/issue 与证据链接，不能用仓库总体 Star 替代单技能质量。

## 适配与上下文

- 与现有技能确定边界，优先条件引用而非创建重叠入口。
- description 聚焦真实触发；保持默认自动发现，除非用户明确要求显式调用。详细流程放 references，保持技能安装包自包含。
- 用 skill-creator 完成新增/修改，遵循当前仓库约定和可用工具；仅在实际安装时使用 skill-installer 或仓库脚本。
- 记录修改前后的 description 字符数及入口大小。运行 scripts/audit_context.py；字符数不冒充精确 Token。预算内保留上限；若超出，先精简并审查触发精度，需要调整时在预算记录说明收益与范围。

## 验证与交付

运行官方 quick_validate，检查 YAML/UI 元数据、引用文件存在、来源与许可随包安装。新增可执行脚本才需要对应行为验证，不为纯说明文件制造形式测试。

先安装到新的隔离 staging 目录，核对源与安装包文件集合及字节；有脚本时从无关 cwd 运行以验证路径独立性。仓库支持时跑安装 -WhatIf、git diff --check 和适用检查。保留其他未提交变更。

交付说明改动、检查结果与限制。结构验证不能宣称真实任务表现已验证；未进行的网络搜索、脚本执行、运行时安装或发布应如实说明。接入说明放仓库 docs，不重复塞入技能入口。
